THE ARGUMENT

The engine is not the product.
The boundary is.

Game engines accumulate sacred objects. Parsers become native subsystems. Tools become executables. Rendering policy becomes permanent. Scripting gets a sandbox above the real engine.

Jess refuses the hierarchy. If something can be a package, a Luau program, an IR, a capability, or data, it does not get a privileged path merely because engines traditionally gave it one.

Native code is a privilege. Make it earn the boundary.

NO PRIVILEGED PATHS

Dehardcode the whole fucking stack.

These are packages, not promises. They run through the same package/runtime boundary available to application code.

DREAMWIND

Bethesda formats and tooling

BSA/BA2 archives, TES3 records, NIFs, saves, OpenMW import semantics, load-order tools and the machinery around them — exported as Luau modules.

@RECAST

Navigation without the C++ ABI

Recast build stages, Detour navmeshes and queries, Crowd, PathQueue and TileCache in Luau over buffers, vectors and compiled hot paths.

@DREAM/SCENE

A scenegraph that owns no renderer

Packed identity, transforms, bounds, masks and traversal. Presentation structure as a package, not an engine singleton.

@DREAM/PHYSICS2D

The solver is Luau

Buffer-backed circles, broadphase, contacts, spatial queries, DDA raycasts and snapshots. Rust is not involved in the simulation.

@DREAM/HTTP

Application protocol, not engine feature

A headless HTTP/1.1 router plus DreamNet request/response transport, with reusable views and lazy parsing on the hot path.

@MAGICK

Raster work without spawning ImageMagick

Pure-Luau PNG/BMP/TGA I/O and image operations, plus the graphics build scripts that used to live as shell machinery.

BUILTIN.JPK

Jess consumes itself too

JSON, TOML, YAML and Luau style tooling live in the built-in package instead of accumulating another permanent Rust subsystem.

@DREAMWEAVE/SITE

Yes, the website generator too.

Markdown, Tera-shaped templates, Sass, search, feeds and static output. Keep scrolling.
