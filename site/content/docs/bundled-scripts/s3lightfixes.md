`@dreamwind/tools/s3lightfixes` is a Luau port of [S3LightFixes](https://github.com/DreamWeave-MP/S3LightFixes) 0.4.59. It rewrites every light in your load order for OpenMW's lighting: whitish lights get warmer and dimmer, colored lights keep their color, radii grow, flicker goes away, and negative lights are nulled. Optionally it relights interior cells too. The result is one plugin, `S3LightFixes.omwaddon`.

It reads the same `lightconfig.toml` and writes the same plugin, `lightconfig.toml`, and `lightconfig.log` as the original, byte for byte, apart from [six deliberate differences](#differences-from-the-original). On a {{ bench(value="plugins") }}-plugin load order it's {{ bench(workload="s3lightfixes", value="faster") }} times faster and uses {{ bench(workload="s3lightfixes", value="less_memory") }} times less memory.

## Run it

```luau
--!strict
-- lights.luau <openmw.cfg>
local config: string = ...
local openmw = jess.openmw.load(config)
local s3lightfixes = require '@dreamwind/tools/s3lightfixes'

s3lightfixes({}, openmw)
```

```sh
$ jess run --package jess/jpk/dreamwind lights.luau ~/.config/openmw/openmw.cfg
# S3LightFixes 0.4.59
# config: /home/you/.config/openmw/openmw.cfg
# output: /home/you/.local/share/openmw/data/S3LightFixes.omwaddon
# content files: 3
# loaded plugins: 3
# masters: 3
# changed cells: 0
# changed lights: 676
LIGH "Light_Com_Candle_01" from "Bloodmoon.esm": color [245, 140, 40, 0] -> [140, 74, 46, 0], radius 128 -> 153, flags LightFlags(DYNAMIC | CAN_CARRY | FIRE | FLICKER_SLOW) -> LightFlags(DYNAMIC | CAN_CARRY | FIRE)
...
S3LightFixes.omwaddon generated and saved in /home/you/.local/share/openmw/data
```

Then enable `S3LightFixes.omwaddon` late in your load order, or set `autoEnable` and let the tool do it. Rerun after every change to your mod list: a light added by a mod you installed afterwards isn't in the output, and keeps its original flicker and color. [Merging and Fixing a Load Order](@/docs/guides/load-order-scripts.md) walks through it from the player's side.

## What it does

**Which plugins.** Every active `.esp`, `.esm`, `.omwaddon`, and `.omwgame` that exists, except its own output and anything `excluded_plugins` matches. They're read in the text encoding OpenMW reads them in, the `encoding=` of your `openmw.cfg` chain (Windows-1252 if none sets it), from the last in the load order to the first, and for each record id the first one seen, so the definition the game actually uses, is the one fixed. Lights whose ids match `excluded_ids` are left alone.

**Each light**, in this order:

1. **Negative lights**: with `disable_negative_lights`, a light with the `NEGATIVE` flag loses it and gets radius 0 and black color. Nothing else happens to it.
2. **Flags**: `disable_flickering` removes `FLICKER` and `FLICKER_SLOW`; `disable_pulse` removes `PULSE` and `PULSE_SLOW`.
3. **Standard or colored**: a light whose hue is between 14 and 64 degrees (the orange-to-yellow of flames and lamps) is *standard*; every other light is *colored*.
4. **Color**: the light's HSV hue, saturation, and value are multiplied by `standard_*` or `colored_*`.
5. **Radius**: multiplied by `standard_radius` or `colored_radius`.
6. **Duration**: multiplied by `duration_mult`. A duration of -1 means the light never burns out, and stays -1.

A light matching a light override follows the override instead, for whatever the override sets; see [light overrides](#light-overrides).

**Cells** are only read when something could change them: `disable_interior_sun`, or an ambient override. Then each interior cell with lighting data can have its sunlight turned off and its ambient, sunlight, fog color, or fog density replaced. Only cells that changed go in the plugin.

**The output**: `S3LightFixes.omwaddon`, author `S3`, description `Plugin generated by s3-lightfixes`, written in the same encoding. Its masters are the plugins it took records from, in load order; the lights come sorted by id, then the cells. An old `S3LightFixes.omwaddon` in `data-local` is deleted first, and the new one is written to the output folder (`output`, else `output_dir`, else `data-local`, else the current folder), which is created if it's missing.

**The log**: a summary and one line per changed record, printed and written to `lightconfig.log` next to your `openmw.cfg`.

## lightconfig.toml

Settings live in `lightconfig.toml`, in the folder of your user `openmw.cfg` (the last one in the config chain; a context's `userConfigDir`). It's found ignoring case, and saved as `lightconfig.toml`. With none there, the first run writes one with the defaults and whatever the run's options set. Unknown keys are ignored.

A complete file with every default:

```toml
disable_interior_sun = false
disable_flickering = true
disable_pulse = false
disable_negative_lights = true
auto_enable = false
no_notifications = false
debug = false
dry_run = false
validate_config = false
standard_hue = 0.62
standard_saturation = 0.8
standard_value = 0.57
standard_radius = 1.2
colored_hue = 1.0
colored_saturation = 0.9
colored_value = 0.7
colored_radius = 1.1
duration_mult = 2.5
excluded_plugins = [
    "deleted_groundcover.omwaddon",
    "Clean_Argonian Full Helms Lore Integrated.ESP",
    "Baldurwind.omwaddon",
    "Crassified Navigation.omwaddon",
    "LuaMultiMark.omwaddon",
    "S3maphore.esp",
    "Toolgun.omwaddon",
]
excluded_ids = []
output_dir = "/home/you/.local/share/openmw/data"
save_config = false

[light_overrides]

[ambient_overrides]
```

### Top-level keys

| Key | Type | Default | Does |
| --- | --- | --- | --- |
| `disable_interior_sun` | boolean or list of patterns | `false` | `true` turns off sunlight in every interior cell (vtastek's shaders for OpenMW 0.47 want this). A list turns it off in the interiors whose id matches a pattern. |
| `disable_flickering` | boolean | `true` | Removes `FLICKER` and `FLICKER_SLOW` from every light. |
| `disable_pulse` | boolean | `false` | Removes `PULSE` and `PULSE_SLOW` from every light. |
| `disable_negative_lights` | boolean | `true` | Nulls negative lights. |
| `auto_enable` | boolean | `false` | Enables the output in `openmw.cfg`, backing the config up first, when it's in a data folder. |
| `no_notifications` | boolean | `false` | Silences the status messages. The log is still printed. |
| `debug` | boolean | `false` | Prints the resolved output folder and override counts. |
| `dry_run` | boolean | `false` | Prints the log of what would change; writes nothing. |
| `validate_config` | boolean | `false` | Checks the config and its patterns, then stops; writes nothing. Can't be combined with `dry_run`. |
| `standard_hue` | number | `0.62` | Multiplies standard lights' hue. |
| `standard_saturation` | number | `0.8` | Multiplies standard lights' saturation. |
| `standard_value` | number | `0.57` | Multiplies standard lights' value (brightness). |
| `standard_radius` | number | `1.2` | Multiplies standard lights' radius. |
| `colored_hue` | number | `1.0` | Multiplies colored lights' hue. |
| `colored_saturation` | number | `0.9` | Multiplies colored lights' saturation. |
| `colored_value` | number | `0.7` | Multiplies colored lights' value. |
| `colored_radius` | number | `1.1` | Multiplies colored lights' radius. |
| `duration_mult` | number | `2.5` | Multiplies every light's duration. |
| `excluded_plugins` | list of patterns | the list above | Plugins to skip, matched against the file name. Setting it replaces the default list, which names plugins the original can't read. |
| `excluded_ids` | list of patterns | `[]` | Light and cell ids to leave alone. |
| `output_dir` | string | `data-local` | The folder to write the plugin to. The first run saves your `data-local` here. |
| `save_config` | boolean | `false` | Saves `lightconfig.toml` on every run, as `updateLightConfig` does once. |

Patterns are regexes in Rust's [`regex` syntax](https://docs.rs/regex/latest/regex/#syntax), and all of them ignore case: `excluded_plugins`, `excluded_ids`, the `disable_interior_sun` list, and the override tables'.

### Light overrides

`[light_overrides."pattern"]` sets values for every light whose id matches the pattern. The **first** override that matches a light is the one used, in the order the file lists them, so put specific patterns before general ones.

```toml
[light_overrides.light_com_candle_02_64]
red = 255
green = 128
blue = 64

[light_overrides."^torch"]
radius_mult = 1.5
duration = 1200.0
flag = ["FIRE", "PULSE_SLOW"]
```

| Field | Type | Does |
| --- | --- | --- |
| `red`, `green`, `blue` | integer, 0 to 255 | A fixed base color. All three or none. |
| `hue` | integer, 0 to 360 | A fixed hue, in degrees. |
| `saturation` | number, 0 to 1 | A fixed saturation. |
| `value` | number, 0 to 1 | A fixed value. |
| `hue_mult`, `saturation_mult`, `value_mult` | number | Multiply the base color's hue, saturation, or value. |
| `red_mult`, `green_mult`, `blue_mult` | number | Multiply the final color's channels, clamped to 0 to 255. |
| `radius` | integer | A fixed radius. |
| `radius_mult` | number | Multiplies the light's radius. |
| `duration` | number | A fixed duration. |
| `duration_mult` | number | Multiplies the light's duration. |
| `flag` | string or list | The light's flags, replacing its own: names from `DYNAMIC`, `CAN_CARRY`, `NEGATIVE`, `FLICKER`, `FIRE`, `OFF_BY_DEFAULT`, `FLICKER_SLOW`, `PULSE`, `PULSE_SLOW`, or `NONE` alone. A list names several; so does one string with the names joined by pipes. |

How an override combines with the global settings:

- **Color**: with `red`/`green`/`blue`, that color is the base, and the HSV components the override doesn't set are left as they are. Without them, the light's own color is the base, and the components the override doesn't set get the global `standard_*`/`colored_*` multipliers. The RGB multipliers apply last.
- **Radius and duration**: the override's `*_mult` or fixed value if it has one, else the global multiplier. A -1 duration is never changed.
- **Flags**: replaced by `flag` after flicker and pulse are removed, so `flag = "FLICKER"` brings flicker back. `CAN_CARRY` is never added or removed.
- A fixed value and its multiplier (`radius` and `radius_mult`, `hue` and `hue_mult`, ...) can't both be set. Out-of-range `hue`, `saturation`, and `value` are clamped.
- `red`, `green`, `blue`, `hue`, and `radius` are integers: `radius = 256.0` is an error.

### Ambient overrides

`[ambient_overrides."pattern"]` sets lighting for every interior cell whose id (its name, lowercased) matches. Unlike light overrides, **every** matching override applies, in order, each replacing what it sets.

```toml
[ambient_overrides."caius cosades' house$"]
fog_density = 0.5

[ambient_overrides."caius cosades' house$".ambient]
red = 64
green = 48
blue = 32
```

| Field | Type | Does |
| --- | --- | --- |
| `ambient` | `{ red, green, blue }` | The cell's ambient color. |
| `sunlight` | `{ red, green, blue }` | The cell's sunlight color. |
| `fog` | `{ red, green, blue }` | The cell's fog color. |
| `fog_density` | number | The cell's fog density. |

Colors are fixed values, 0 to 255, all three channels. Older configs that give a color as `{ hue, saturation, value }` still read, converted to RGB.

## Options from Luau

Everything in `lightconfig.toml` can also be set for one run, in `state.s3lightfixes`, in camelCase:

```luau
local state = {}

state.s3lightfixes = {
  disablePulse = true,
  standardRadius = 1.5,
  excludedIds = { '^light_6th' },
  lightOverrides = {
    { id = '^light_com_lantern', radius = 400, red = 255, green = 160, blue = 80 },
    { id = '^torch', durationMult = 4, flag = 'FIRE' },
  },

  ambientOverrides = {
    {
      id = 'caius cosades\' house$',
      ambient = { red = 64, green = 48, blue = 32 },
      fogDensity = 0.5,
    },
  },
  disableInteriorSun = { '^vivec, ' },
}
```

```
LIGH "torch_infinite_time" from "Morrowind.esm": color [245, 140, 40, 0] -> [140, 74, 46, 0], radius 256 -> 384, duration 300 -> 1200, flags LightFlags(DYNAMIC | CAN_CARRY | FLICKER | FIRE | OFF_BY_DEFAULT) -> LightFlags(CAN_CARRY | FIRE)
```

Options lay over the file, each the way its S3LightFixes command-line flag does:

| Option | Type | Original's flag | Combines with the file by |
| --- | --- | --- | --- |
| `disableInteriorSun` | boolean, or a list of patterns | `-7`, `--classic` | Replacing it. |
| `disableFlickering` | `boolean` | `-f`, `--no-flicker` | Replacing it. |
| `disablePulse` | `boolean` | `-p`, `--no-pulse` | Replacing it. |
| `disableNegativeLights` | `boolean` | `--disable-negative-lights` | Replacing it. |
| `autoEnable` | `boolean` | `-e`, `--auto-enable` | Turning it on; `false` can't turn the file's `true` off. |
| `noNotifications` | `boolean` | `-n`, `--no-notifications` | Turning it on. |
| `debug` | `boolean` | `-d`, `--debug` | Turning it on. |
| `dryRun` | `boolean` | `--dry-run` | Replacing it; `true` also turns `validateConfig` off. |
| `validateConfig` | `boolean` | `--validate-config` | Replacing it; `true` also turns `dryRun` off. |
| `updateLightConfig` | `boolean` | `-U`, `--update-light-config` | Saving `lightconfig.toml` this run, options included. |
| `standardHue`, `standardSaturation`, `standardValue`, `standardRadius` | `number` | `--standard-hue`, `-s`, `-v`, `-r` | Replacing them. |
| `coloredHue`, `coloredSaturation`, `coloredValue`, `coloredRadius` | `number` | `-H`, `-S`, `--colored-value`, `-R` | Replacing them. |
| `durationMult` | `number` | `-M`, `--duration-mult` | Replacing it. |
| `output` | `string` | `-o`, `--output` | Replacing `output_dir`. The folder must exist. |
| `excludedIds` | `{ string }` | `-x`, `--excluded-ids` | Adding to the file's list the patterns it doesn't have yet. |
| `excludedPlugins` | `{ string }` | `-X`, `--excluded-plugins` | Adding to the file's list the patterns it doesn't have yet, ignoring case. |
| `lightOverrides` | `{ { id: string, ... } }` | `--light` | Adding after the file's; one with the same pattern as a file entry replaces it and moves to the end. |
| `ambientOverrides` | `{ { id: string, ... } }` | `--ambient` | The same. |

An override option is a table with the pattern in `id` and the TOML fields in camelCase: `radiusMult`, `durationMult`, `hueMult`, `redMult`, `fogDensity`, and so on. `flag` takes a string (`"FIRE | PULSE_SLOW"`) or a list. Ambient colors are `{ red, green, blue }` tables. Options are checked exactly as the file is, so `{ id = "x", radius = 1, radiusMult = 2 }` fails with ``light override x: Fields `radius` and `radius_mult` are mutually exclusive``.

The original's `-c`/`--openmw-cfg` is the config your script hands `jess.openmw.load`. `--generate-completion` and `--generate-manpage` have no equivalent; `jess completions` and `jess man` cover jess itself.

## Writing files

| File | Written when |
| --- | --- |
| `S3LightFixes.omwaddon` | Every run but a dry run or validation. |
| `lightconfig.toml` | When there isn't one, when it says `save_config = true`, or with `updateLightConfig`, and never on a dry run or validation. It's written with the run's options included. |
| `lightconfig.log` | Every run but a dry run or validation. |
| `openmw.cfg` | Only with `autoEnable`, when the plugin isn't enabled yet and was written to a data folder (elsewhere, OpenMW couldn't load it, so it's left disabled with a message). The config is backed up to `openmw.cfg.bak` (`.bak1`, ... if that exists) first, and left alone if that copy fails. |

Because saving writes the options into the file, options you meant for one run stick if the run saved the config. That includes the first run, which saves a new `lightconfig.toml`. `excludedIds` and `excludedPlugins` are *added* to the file's lists, each only if the list doesn't have it yet, so saving with them every run (`updateLightConfig` or `save_config = true`) lists them once.

## Report

Afterwards `state.s3lightfixes.report` holds what happened, for whatever runs next:

| Field | Type | What |
| --- | --- | --- |
| `output` | `string` | The plugin written. |
| `masters` | `number` | How many plugins it took records from. |
| `objects` | `number` | How many records it took. |
| `lights` | `number` | Lights in the plugin. |
| `cells` | `number` | Cells in the plugin. |
| `enabled` | `boolean` | With `autoEnable`, whether the plugin is enabled in `openmw.cfg` now. Always `false` without it. |
| `logs` | `{ { kind, plugin, id, changes } }` | Every changed record: `kind` is `"LIGH"` or `"CELL"`, `changes` the log line's parts. |

```luau
local config: string = ...
local openmw = jess.openmw.load(config)
local s3lightfixes = require '@dreamwind/tools/s3lightfixes'
local state = { s3lightfixes = { noNotifications = true } }

s3lightfixes(state, openmw)

local report = state.s3lightfixes.report
print(
  `{report.lights} lights and {report.cells} cells from {report.masters} plugins -> {report.output}`
)

for _, log in report.logs do
  if log.kind == 'CELL' then print(log.id, table.concat(log.changes, '; ')) end
end
```

A dry run's report is `{ dryRun = true, masters, objects, logs }`, and a validation's `{ validated = true }`.

The run stops with an error when `lightconfig.toml` can't be read, a pattern doesn't compile (every bad pattern is listed), an override is invalid, `output` isn't a folder, there's no content to fix, or no light or cell is left to write (everything excluded).

## Differences from the original

The plugin, `lightconfig.toml`, and `lightconfig.log` match S3LightFixes 0.4.59's byte for byte, except:

- **Overrides apply in listed order.** The original sorts overrides by pattern before matching, so which of two overlapping light overrides wins depends on how the patterns sort. Here the first one listed wins, and a saved `lightconfig.toml` lists them in the order you wrote them.
- **A light override's `flag` never changes `CAN_CARRY`.** In the original, `flag` replaces all of a light's flags, so an override could turn a carryable torch into a fixture or the other way round. That breaks saves and inventories holding the light, which is a lot of damage for a lighting tweak. Here `CAN_CARRY` stays as it was, whatever `flag` says.
- **`disable_interior_sun` takes a list.** Besides `true` and `false`, it takes cell id patterns, to turn off sunlight in just those interiors.
- **Override patterns ignore case.** The original lowercases light and cell ids but matches override patterns as written, so a pattern with a capital letter, like its README's `[light_overrides.Torch_000]`, never matches. Here override patterns ignore case, as its exclusion patterns already do.
- **Exclusions are saved once.** The original appends `--excluded-ids` and `--excluded-plugins` to the file's lists every time it saves them, so a config saved on every run grows with each run, forever. Here a pattern already listed isn't added again (plugin patterns compared ignoring case), and repeats already in the file are dropped when it's saved.
- **Text is read in `openmw.cfg`'s encoding.** The original reads every plugin as Windows-1252, so on a Russian or Polish install its log shows ids garbled and patterns can't match their letters. Here plugins are read, and the output written, in the `encoding=` OpenMW uses.

It also runs as a module rather than an app: there are no GUI dialogs (`noNotifications` only silences the messages), no `--classic` flag (set `disableInteriorSun = true`), and it's configured through `lightconfig.toml` and `state` rather than command-line flags.
