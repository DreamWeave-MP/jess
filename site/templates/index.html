JESS // A NATIVE APPLICATION KERNEL FOR LUAU

Rust exposes reality. Luau decides what it means.

Jess is the native kernel under a Luau application. It owns the operating system, the hardware, resource lifetimes, and the trust boundary, and nothing else. The game, the tool, the editor, and the site you are reading are packages, each running with exactly the capabilities it asked for.

WHAT THE KERNEL DOES

Small on purpose.
Everything that means something is a package.

Script domains

One isolated Luau authority per domain: the contexts that say when its code runs, the capability grant that says what it may do, workers that talk to it in messages, a generation that moves on every restart, and an ownership registry that teardown releases. The runtime knows nothing about games, editors, or windows.

Packages

A JPK is an immutable archive of Luau with a manifest: modules, layers, dependencies, command targets, and the capabilities each one needs. A source folder behaves the same way above the provider boundary. Exports are inert; requiring one starts nothing. Activated layers run their entrypoints once, in dependency order.

Capabilities

Nothing optional is granted unless the operator asks. Files, environment, processes, TCP, DNS, and TLS are named capabilities, denied by default, checked at the native seam. A package cannot grant itself one, and running from a source folder gives code no power the packed archive would lack.

Native lowering

Luau runs on L3i with native code generation on. jess run --profile prints call, sampling, and native-block statistics; --emit-asm writes the generated assembly; --disassemble the bytecode. The hot paths below are Luau, measured, not Rust with a Luau face.

Typed from the start

jess luau-types writes a type stub for every module, native or built-in, and jess init wires them into an editor. Package code is --!strict and --!native; @jess/style, the repository's own style checker, runs on Luau's parser and ships inside the binary.

Presentation as data

A backend-independent render graph with targets, passes, culling, and aliasing; a typed shader IR that lowers deterministically to WGSL from ordinary Luau; an input action graph with sets, layers, and intents; localization bundles with ICU MessageFormat semantics. None of them knows what application they serve.

WHAT RUNS ON IT

Packages, not promises.

Each of these goes through the same package and capability boundary any application does. There is no second, private framework for the first-party work.

DREAMWIND

Bethesda formats, in Luau

TES3 plugins and saves, raw-preserving: an untouched record saves as its original bytes. NIF for every version OpenMW reads. BSA and BA2 archives. OpenMW's config chain and virtual filesystem, resolved the way the engine resolves them.

TES3MERGE · MERGED LANDS · S3LIGHTFIXES

The load-order tools

Ports of three native tools, held to byte-level comparison with the originals' output on a real load order, each with a command target and a bench that checks its answer.

@RECAST

Navigation without the C++ ABI

Recast's build stages, Detour tiles, queries and paths, the crowd, the tile cache, and tiled navmeshes, over buffers and typed records.

@DREAM/SCENE · @DREAM/PHYSICS2D · @DREAM/ECS

Simulation state the kernel never sees

A scenegraph with packed identity and incremental bounds, a buffer-backed 2D solver with a grid broadphase, and an archetype ECS whose hot queries lower from JessQL once into cached plans.

@JESSQL · @DREAMWIND-SQL

A relational engine for anything with rows

SQL over in-memory tables and over providers: the VFS, TES3 records, and NIF blocks answer the same queries, with pushdown for prefix, order, and limit.

@DREAM/HTTP

Application protocol, not engine feature

An HTTP/1.1 router and request views with lazy parsing on the hot path, and the request and response pairs over the transport the runtime exposes.

@MAGICK

Raster work without spawning ImageMagick

PNG, BMP, and TGA in and out, resizing, compositing, and the graphics build steps that used to be shell scripts.

@DREAMWEAVE/SITE

Yes, the website generator too.

Markdown, Tera-shaped templates, Sass, search, feeds, and static output. The dev server that rebuilds this page when a file changes is one Luau file over a TCP poller. Keep scrolling.

DOGFOOD

This site is a Jess workload.

The generator is a package. The build is a command target that activates it with the file capabilities it declares and nothing else. The dev server is another target with a TCP listener added. No Zola, no Node, no Python in the loop.
